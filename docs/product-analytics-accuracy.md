B2C only. This corrects the existing SQL projection, calculator, types, screen and instrumentation from #3039. It adds no table, dependency, service, identifier or third-party recipient. The applied #3039 migration is unchanged.

## Coverage and privacy

Aggregate coverage exposes counts/status, never a directory column containing an individual's enabled preference, consent date or consent version. The service-only RPC may read the current preference timestamp to assess temporal applicability; own preference and event endpoints contain no athlete identities. Historical optional use remains unknown before opt-in, during absent instrumentation, after withdrawal or after 180-day expiry. Latest consent cannot reconstruct earlier intervals. “Measured” means tracking is applicable and available, not guaranteed delivery from every device.

Default-off consent, minors/unknown-age rejection, row-level security, authenticated server-bound actors, server timestamps, allowlisted event names, retry/daily deduplication, caps and retention locks remain. The forward migration additionally rejects excluded profiles and non-athlete roles at consent/ingestion. Internal-registry opt-ins are refused; loading their own preference returns false so browser tracking stays silent. Technical failures remain in Sentry/existing diagnostics; no exception text, training notes or medical/nutrition contents enter events.

## Deletion and historical limits

Production catalog checks confirmed: deleting a plan cascades its session_completions and linked today_checkins; sparring plan references become null. Deleting a profile cascades check-ins, training and optional events/preferences. These behaviours are unchanged. Soft-deleted manual sessions are omitted. Deleted source records can reduce historical active users, retention, conversions and first/last activity, including when a plan deletion removes training evidence. Existing optional events follow their existing 180-day/account deletion rules; no new durable personal history or anonymised aggregate is justified or added. Legacy training sessions have no reliable identifier joining them to newer session identities, so the verified distinct total explicitly excludes that legacy source.

Historical usable-state transitions are unavailable: the funnel uses current plan status and creation time, not an invented ready timestamp. Optional opens before this correction could represent data fetches rather than visits; production had no events at the read-only audit, so none were reinterpreted or backfilled.
